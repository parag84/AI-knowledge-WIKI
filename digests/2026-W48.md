_2026-11-23 to 2026-11-29 · 40 new videos · 257 new insights · 0 knowledge changes_

**Agents are moving out of the chat window: WebMCP, plugin side panels and Microsoft's Agent Host Protocol all assume a user's own agent acting inside live UIs across multiple surfaces, so Parag's AX and component work now has to cover shared sessions, approvals and tool exposure, not just chat.**

## Top insights

1. WebMCP is a new browser standard letting a site expose tools that a user's agent calls in a WebMCP-enabled browser, updating the live app; it is pitched as faster and cheaper than computer-use because the agent queries the backend instead of clicking through UI.
   - _Why it matters:_ WebMCP lets a site expose tools to the user's agent instead of being clicked through, which changes how design systems and developer portals should define agent-callable actions alongside visual UI.
   - Source: [Sites and the Next Generation of Web Apps | DevDay 2026](https://github.com/parag84/AI-knowledge-WIKI/blob/main/knowledge/videos/2026-11-11-sites-and-the-next-generation-of-web-apps-devday-2026.md)
2. AHP separates where an agent runs (host) from where it is controlled (clients). A joining client receives a snapshot of the full conversation, workspace state, tool calls and pending approvals, so any surface can render and act on the same live session.
   - _Why it matters:_ AHP's host/client split with snapshots of conversation, tool calls and pending approvals defines the state model an AI component library needs to render the same live session on any surface.
   - Source: [The Agent Has Left the Chat - Harald Kirschner, Microsoft](https://github.com/parag84/AI-knowledge-WIKI/blob/main/knowledge/videos/2026-11-13-the-agent-has-left-the-chat-harald-kirschner-microsoft.md)
3. Developers want to see background sub-agents, because an agent blocked waiting on five sub-agents looks idle. AHP therefore models sub-agents as separate chats, including their tool calls, and these can be popped out into their own session view.
   - _Why it matters:_ Modeling sub-agents as separate, pop-out chats addresses the 'blocked agent looks idle' problem and is a concrete supervision pattern for AX components.
   - Source: [The Agent Has Left the Chat - Harald Kirschner, Microsoft](https://github.com/parag84/AI-knowledge-WIKI/blob/main/knowledge/videos/2026-11-13-the-agent-has-left-the-chat-harald-kirschner-microsoft.md)
4. Side-panel widgets share user selection state with the model, so selecting an element (e.g. a molecule region or a page element) becomes conversational context. This uses MCP app methods such as update model context and send message.
   - _Why it matters:_ Side-panel widgets sharing selection state with the model turn UI selection into conversational context, a core intent-driven pattern for component APIs.
   - Source: [Build What’s Next on the ChatGPT Platform with Plugins | DevDay 2026](https://github.com/parag84/AI-knowledge-WIKI/blob/main/knowledge/videos/2026-11-11-build-what-s-next-on-the-chatgpt-platform-with-plugins-devda.md)
5. The ChatGPT in-app browser now supports 'annotation extensibility': developers embed custom annotations in HTML (custom controls, suggested prompts) that tell Codex how a site can be edited, which the speakers call especially useful for design systems and component libraries.
   - _Why it matters:_ Annotation extensibility lets component libraries embed hints in HTML about how agents may edit them, a direct new surface for design-system governance.
   - Source: [Sites and the Next Generation of Web Apps | DevDay 2026](https://github.com/parag84/AI-knowledge-WIKI/blob/main/knowledge/videos/2026-11-11-sites-and-the-next-generation-of-web-apps-devday-2026.md)

## Suggested experiments

- **Agent session state for Lit components** (medium): Prototype Lit components (approval card, tool-call row, sub-agent chip) driven by an AHP-style snapshot object that includes pending approvals and first-wins resolution. Render the same snapshot in two tabs to check that approvals, reconnect replay and sub-agent pop-out behave consistently.
- **WebMCP and annotation pass on a developer portal page** (small): Take one developer portal flow, such as creating an API key or searching endpoints, and list the tools it would expose via WebMCP, plus HTML annotations describing which components an agent may edit. Note where design tokens or component contracts need new metadata so agents and humans can co-edit safely.
- **Three-state tool result and intent-sized responses** (small): Add an 'unknown' state next to success and failed in the tool-call component, with a verification ID and no auto-retry affordance. Also define response-format rules by intent: text only, a single-item card or a full-plan card. Test both with a few designers on realistic agent edits.
