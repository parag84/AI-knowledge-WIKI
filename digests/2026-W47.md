**The strongest shift this week is that agent supervision is moving from reading code to reviewing evidence (videos, screenshots, summaries, visible diffs, provenance badges), which turns 'approval and verification UI' into a core AX design surface rather than an afterthought.**

## Top insights

1. Telling a single agent in its instructions to wait for human approval does not guarantee it will wait; a deterministic workflow node that pauses execution is needed to enforce human-in-the-loop review.
   - _Why it matters:_ Prompt instructions alone do not enforce human approval, so your approval UI patterns need to sit on a deterministic pause node, and the component library should model that state explicitly.
   - Source: [Why everyone is talking about graphs in AI (and when to skip them)](https://github.com/parag84/AI-knowledge-WIKI/blob/main/knowledge/videos/2026-11-19-why-everyone-is-talking-about-graphs-in-ai-and-when-to-skip.md)
2. Trust in agent output comes from attaching provenance to the PR: the full conversation, the tools used, before and after screenshots, and a video of a verification agent clicking through the app in a browser.
   - _Why it matters:_ It defines a concrete provenance bundle (conversation, tools used, before/after screenshots, verification video) that you could standardise as an AI component pattern for trust in agent output.
   - Source: [How to build an agent that builds the culture — Zach Bruggeman, Ramp](https://github.com/parag84/AI-knowledge-WIKI/blob/main/knowledge/videos/2026-11-20-how-to-build-an-agent-that-builds-the-culture-zach-bruggeman.md)
3. Build a dev-only inspector route per component that renders it standalone with dummy data and one-click presets (welcome, thinking, day/week proposal, error). This lets you check AI-dependent UI states without replaying multi-step flows or calling the model each time.
   - _Why it matters:_ A per-component inspector with presets for states like thinking, proposal and error maps directly onto testing streaming, tool-call and approval components in a Lit library without calling the model each time.
   - Source: [Build a hidden edit mode for your AI app with reusable agent skills](https://github.com/parag84/AI-knowledge-WIKI/blob/main/knowledge/videos/2026-11-17-build-a-hidden-edit-mode-for-your-ai-app-with-reusable-agent.md)
4. The annotations API lets you declare which DOM elements are selectable in the in-app browser's annotate mode. For example, you can make individual design-system components selectable while excluding the Storybook frame or an emulator chrome.
   - _Why it matters:_ The annotations API lets you make individual design-system components selectable for agents while excluding Storybook chrome, which affects how you expose your component library to coding agents.
   - Source: [New Ways of Working with Codex — Dominik Kundel & Charlie Guo, OpenAI](https://github.com/parag84/AI-knowledge-WIKI/blob/main/knowledge/videos/2026-11-17-new-ways-of-working-with-codex-dominik-kundel-charlie-guo-op.md)
5. In Whiteboards, a user can drag a box around a messy region and ask Claude about only that selection. This spatial-selection-as-scope pattern lets the user set the agent's context through direct manipulation instead of prompting.
   - _Why it matters:_ Spatial selection as agent scope, alongside the visible-diff pattern in Sheets (t2Zo3YAJdj4-2), is an intent-driven alternative to prompting that you can reuse in AX interfaces.
   - Source: [Five brand new ways to use Claude at work](https://github.com/parag84/AI-knowledge-WIKI/blob/main/knowledge/videos/2026-11-18-five-brand-new-ways-to-use-claude-at-work.md)

## Suggested experiments

- **Inspector page for AI chat components** (medium): Build a dev-only Storybook or standalone route for one Lit AI component, such as the tool-call or approval card. Add one-click presets for idle, streaming, awaiting-approval, error-with-retry and completed, and split the state panel into editable, props and computed groups. If it works, ask a coding agent to turn it into a reusable 'inspector generator' skill and try it on a second component.
- **Provenance and evidence block component** (medium): Prototype a framework-agnostic web component that attaches agent evidence to an output: tools used, a before/after screenshot pair, a link to the verification recording and a 'certified/verified' badge state. Test it in a mock PR view and a mock chat reply, then check whether reviewers can approve without opening the code.
- **Agent-ready design system context in the dev portal** (small): Expose your design-system components to a coding agent via annotations or an MCP/@-mention context entry that injects each component's tokens, props and usage rules. Compare how many corrections are needed when generating a portal page with and without that injected context.
