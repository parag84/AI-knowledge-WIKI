**The center of gravity in agentic UX is moving from reading agent output to supervising through evidence, such as videos, provenance on PRs, visible diffs and component inspectors, and that is a design problem Parag's component library and portal work can own directly.**

## Top insights

1. Build a dev-only inspector route per component that renders it standalone with dummy data and one-click presets (welcome, thinking, day/week proposal, error). This lets you check AI-dependent UI states without replaying multi-step flows or calling the model each time.
   - _Why it matters:_ A per-component inspector route with presets (thinking, proposal, error) is a direct pattern for testing AI component states in a Lit library without calling the model each time.
   - Source: [Build a hidden edit mode for your AI app with reusable agent skills](https://github.com/parag84/AI-knowledge-WIKI/blob/main/knowledge/videos/2026-11-17-build-a-hidden-edit-mode-for-your-ai-app-with-reusable-agent.md)
2. Trust in agent output comes from attaching provenance to the PR: the full conversation, the tools used, before and after screenshots, and a video of a verification agent clicking through the app in a browser.
   - _Why it matters:_ Provenance bundles (conversation, tools used, before/after screenshots, verification video) define what an approval or review UI component needs to show to earn trust.
   - Source: [How to build an agent that builds the culture — Zach Bruggeman, Ramp](https://github.com/parag84/AI-knowledge-WIKI/blob/main/knowledge/videos/2026-11-20-how-to-build-an-agent-that-builds-the-culture-zach-bruggeman.md)
3. Telling a single agent in its instructions to wait for human approval does not guarantee it will wait; a deterministic workflow node that pauses execution is needed to enforce human-in-the-loop review.
   - _Why it matters:_ Human-in-the-loop has to be enforced by a deterministic pause node, not a prompt, which shapes how approval UI connects to the agent runtime and what states it must handle.
   - Source: [Why everyone is talking about graphs in AI (and when to skip them)](https://github.com/parag84/AI-knowledge-WIKI/blob/main/knowledge/videos/2026-11-19-why-everyone-is-talking-about-graphs-in-ai-and-when-to-skip.md)
4. In Claude Sheets, every edit Claude makes is outlined as it lands while humans edit the same cells. This is a concrete visible-diff pattern for supervising agent changes in multiplayer artifacts.
   - _Why it matters:_ Outlining each agent edit as it lands next to human edits is a concrete visible-diff pattern that could become a reusable token and component treatment.
   - Source: [Five brand new ways to use Claude at work](https://github.com/parag84/AI-knowledge-WIKI/blob/main/knowledge/videos/2026-11-18-five-brand-new-ways-to-use-claude-at-work.md)
5. The annotations API lets you declare which DOM elements are selectable in the in-app browser's annotate mode. For example, you can make individual design-system components selectable while excluding the Storybook frame or an emulator chrome.
   - _Why it matters:_ Declaring which design-system components are selectable for agent annotation, while excluding the Storybook frame, points to a markup convention a Web Component library could ship by default.
   - Source: [New Ways of Working with Codex — Dominik Kundel & Charlie Guo, OpenAI](https://github.com/parag84/AI-knowledge-WIKI/blob/main/knowledge/videos/2026-11-17-new-ways-of-working-with-codex-dominik-kundel-charlie-guo-op.md)

## Suggested experiments

- **Inspector page for one AI chat component** (medium): Pick one Lit component, such as the chat message or the tool-call approval card, and build a dev-only inspector route with presets for welcome, streaming, awaiting approval and error. Split the state panel into editable, from-props and computed groups. Then ask a coding agent to turn the result into a reusable 'inspector generator' skill.
- **Provenance and approval card spec** (small): Design an approval component variant that shows what the agent did, which tools it used, a before/after diff or screenshot, and a field for the human's reason. Mock it against the refund-style flow: parallel checks, then a rules node, then human review, then a drafted reply. Validate that the pause and resume states are explicit.
- **Agent-selectable components in Storybook** (small): Add a data attribute convention, such as data-agent-selectable, to design-system components and exclude the Storybook chrome. Test whether an agent given component-scoped selection, or an appshot with the accessibility tree, makes more accurate fixes than one given a plain screenshot. Write up the convention for the team as a possible library default.
