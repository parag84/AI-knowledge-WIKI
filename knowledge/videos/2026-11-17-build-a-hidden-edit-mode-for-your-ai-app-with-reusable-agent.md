# Build a hidden edit mode for your AI app with reusable agent skills

[![Build a hidden edit mode for your AI app with reusable agent skills](../assets/thumbs/1fJVOyLmtOI.webp)](https://www.youtube.com/watch?v=1fJVOyLmtOI)

**Google Cloud Tech** · 2026-11-17 · 31:46 · relevance 4/5 · [Watch on YouTube](https://www.youtube.com/watch?v=1fJVOyLmtOI)

## Summary

A Google Cloud Tech 'Build It' episode where Devin Chasanoff shows a dev-only Component Inspector he built into a Gemini-powered personal trainer app using Google Antigravity, without writing code. Each inspected component runs standalone with one-click state presets, a state panel split into editable, props and computed (read-only) state, and plain-English tests that sync both ways with the live view; generation and updates are packaged as reusable agent skills plus an 'Inspector mode' rule. The takeaway is a workflow: perfect one component first, then have the agent turn the process into skills and rules, which saves clicks, tokens and API calls when iterating on AI UI states.

## Key insights

- Build a dev-only inspector route per component that renders it standalone with dummy data and one-click presets (welcome, thinking, day/week proposal, error). This lets you check AI-dependent UI states without replaying multi-step flows or calling the model each time.
  - _Relies on:_ Presets shown for coach chat: welcome, with context, day proposal, week proposal, AI thinking; Avoids repeated Gemini API calls and token waste _(as of 2026-11-17)_
- Split the inspector's state panel into three groups: editable state, state from props (both changeable) and computed state (read-only). This shows how data flows from parent components.
- List the component's tests in plain English on the inspector page and wire them both ways: clicking a test sets up the component for that case, and changing state highlights which tests are active.
- Refine the inspector on one component first (the 'current set card'), then ask the agent to turn the finished result into a reusable skill ('component Inspector generator') plus a second skill for updating an existing inspector page. A new inspector for another card was then generated from one prompt in about seven minutes.
  - _Relies on:_ Skill name: component Inspector generator; Separate update skill for existing inspector pages; Took three attempts: AI Studio proof of concept, a failed big upfront Gemini web app prompt, then incremental work in Antigravity _(as of 2026-11-17)_
- The inspector UI is generated statically from the code file, so it goes stale. Rather than live code introspection, the author added a session-scoped 'Inspector mode' rule, so while the mode is on the agent updates the component and its inspector page in the same request.
  - _Relies on:_ Rule was first a global toggle and was changed to be scoped per session; A 'last updated' chip shows when the inspector page was last regenerated; Inspector mode is turned on and off with natural language _(as of 2026-11-17)_
- Live UX fixes made through the inspector: a chat error state with a retry button, an expandable target-context panel that is open by default, and a modify-proposal chip inside the chat input. The input also wraps text and grows upward for a few lines before scrolling.
  - _Relies on:_ Error presets: connection error, 500 error, simulate timeout _(as of 2026-11-17)_

## How this applies to AX / design systems

This is essentially an agent-generated, Storybook-like inspector, and it suits AI components whose states are expensive to reach, such as streaming 'thinking', proposal or approval cards and error/retry. Parag could prototype a Lit-based inspector page for chat and tool-approval components with presets, the editable/props/computed state panel and plain-English test lists, then capture the generator as an agent skill in the design system repo. The chip-in-input context pattern and the collapsible target-context panel are worth adding as documented AI chat component variants.

_Relevance 4/5: A Storybook-like state inspector for AI chat, proposal and error states, generated by agent skills, maps directly onto Parag's AI component library and design-system work, though it is a single-app demo rather than a reusable library._
