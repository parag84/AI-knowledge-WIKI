## Current best understanding

**Supervising agents is now a design problem with known patterns (Nov 2026).** Trust comes from deterministic structure, not instructions. The patterns: separate *proposing* from *acting*, with structured proposals, read-only pipelines, approval cards and a deterministic referee (Scribant, SRE referee, Trustline payments). Enforce HITL with workflow nodes or code instead of prompts (Google ADK, Amazon gates). Encode every correction as a lint, type or API change. Autonomy is earned on ladders: Meta on-call L1–L3, Factory L1–L4 by regret-free merge rate, and observe→propose→act-and-notify→autonomous with canaries. Review is routed by risk tier (Anthropic, Block). Human surfaces converge on a few pieces: daily digests with one-tap approvals; provenance on PRs (conversation, tools, screenshots, verification video); and showing the latest *semantic step* instead of every tool call (Antigravity). Tool results should allow an **unknown** state beside success and failure, and write tools should return verifiable IDs. Protocols for these UIs are maturing: AHP 1.0 (Oct 2026) separates host from clients, syncs pending approvals and MCP state, shows subagents as their own chats, and uses first-wins conflict rules. OpenAI's Agents API exposes turn grouping and streamed session events. WebMCP lets sites expose tools to the user's own agent. MCP events and MCP tasks replace polling.

**Architecture.** The dominant shape is an orchestrator with isolated-context subagents. Examples: Claude Code projects (beta) with Fable 5.2 orchestrating Opus 5.5 threads, Antigravity Markdown subagents with per-agent tool scopes, and Codex/Sol runs with 5,800+ subagent sessions. This only works now that models are strong enough; Lovable's 2023 multi-agent attempt failed. Fable-class models (Fable 5.x, GPT-6 Astra, Gemini 4 Carbon) brute-force well-specified goals over ~12-hour runs. That makes goal definition, tool provisioning and short outcome-based prompts ("jobs, not tasks") the key human skills. Harnesses should be re-tested on each model upgrade, because old scaffolding becomes a drag. Durable designs use append-only, forkable event logs kept separate from per-model prompts, stateless workers and suspend/resume. Memory needs dedup and conflict resolution (Vertex Memory Bank) or consolidation passes (Anthropic "dreaming"). Markdown memory bloats.

**Evals and cost.** Grade actual system state and inspect trajectories. Use pass^k for customer-facing agents and keep graders isolated, because agents do cheat. Agent-as-judge (~90% expert agreement) and typed yes/no decision models (ZoomInfo: 10x faster, 40x cheaper) both beat plain LLM judges. Cost comes down through cheap per-task models, small distilled models trained on your own traces, MCP servers kept to roughly 50 tools or fewer (or a CLI or code mode), and semantic layers that ground agents in business definitions.

## Latest active insights

- Cited stats motivate the problem: PagerDuty reports ~70% of orgs run 2+ agents in production and 85% want better error detection; a Cloud Security Alliance survey is cited as attributing 65% of production incidents to AI agents. ([Multi-Agent SRE: What Happens When Your Agents Want Opposite Things - Aditi Mewada, Apple](../videos/2026-11-22-multi-agent-sre-what-happens-when-your-agents-want-opposite.md), 2026-11-22, relevance 3/5)
- Roll out agent autonomy in stages: observe → propose → act-and-notify with human approval and postmortem trail → autonomous for small tasks with restore snapshots and canaries (e.g., 20% traffic) before 100%. Always escalate priority ties, repeated conflicts and large blast-radius actions to humans. ([Multi-Agent SRE: What Happens When Your Agents Want Opposite Things - Aditi Mewada, Apple](../videos/2026-11-22-multi-agent-sre-what-happens-when-your-agents-want-opposite.md), 2026-11-22, relevance 3/5)
- Suggested priority order: safety/security > availability/SLO > performance > cost, plus domain pre-checks like minimum headroom (e.g., two AZs always up), incident freezes, and cost caps (e.g., block if over $500/hour). ([Multi-Agent SRE: What Happens When Your Agents Want Opposite Things - Aditi Mewada, Apple](../videos/2026-11-22-multi-agent-sre-what-happens-when-your-agents-want-opposite.md), 2026-11-22, relevance 3/5)
- Conflict pairs (e.g., scale up vs scale down, drain zone vs terminate nodes) should be predefined from incident data, letting non-clashing actions run in parallel; repeated opposing proposals on the same target (e.g., 3 times in 10 minutes) signal a policy bug to escalate to a human. ([Multi-Agent SRE: What Happens When Your Agents Want Opposite Things - Aditi Mewada, Apple](../videos/2026-11-22-multi-agent-sre-what-happens-when-your-agents-want-opposite.md), 2026-11-22, relevance 3/5)
- Leases carry a time-to-live of roughly the proposal ETA × 2 (or ×3) to allow bounded retries; after expiry the action is stopped and the next proceeds. ([Multi-Agent SRE: What Happens When Your Agents Want Opposite Things - Aditi Mewada, Apple](../videos/2026-11-22-multi-agent-sre-what-happens-when-your-agents-want-opposite.md), 2026-11-22, relevance 3/5)
- The referee should be pure deterministic code with no LLM, performing three steps: detect conflicts, rank by priority, and lease the target. Stale plans (base version ≠ current state version) are sent back to re-plan, outranked proposals are deferred, and ties go to the on-call human. ([Multi-Agent SRE: What Happens When Your Agents Want Opposite Things - Aditi Mewada, Apple](../videos/2026-11-22-multi-agent-sre-what-happens-when-your-agents-want-opposite.md), 2026-11-22, relevance 3/5)
- Separate proposing from acting: agents only emit structured proposals (agent identity and owner, verb + target, base version, priority, ETA, evidence) into a queue, and a separate executor performs approved actions. ([Multi-Agent SRE: What Happens When Your Agents Want Opposite Things - Aditi Mewada, Apple](../videos/2026-11-22-multi-agent-sre-what-happens-when-your-agents-want-opposite.md), 2026-11-22, relevance 3/5)
- Agents make it trivial to implement any file format, which risks diverging implementations, as in a recent example of a tar archive crafted so different tar implementations read it differently. He argues for shared open protocols and specs that humans agree on, rather than forks. ([Build the Workshop Before the Software Factory — Armin Ronacher, Earendil](../videos/2026-11-22-build-the-workshop-before-the-software-factory-armin-ronache.md), 2026-11-22, relevance 4/5)
- Code mode, an idea he credits to Cloudflare, gives the agent JavaScript to run in addition to Bash, and tool calls happen through that code instead of through the context window. Combined with cheap, fast classifier or decision models at each branch, an agent can build on-demand workflows, for example triaging 3,000 support requests in a fraction of the time it previously took. ([Build the Workshop Before the Software Factory — Armin Ronacher, Earendil](../videos/2026-11-22-build-the-workshop-before-the-software-factory-armin-ronache.md), 2026-11-22, relevance 4/5)
- Durable agents should be able to suspend and resume, including their sandbox, so they can restart themselves on long overnight runs and take advantage of cheaper flex-scheduled inference, where minutes can pass with no tokens arriving. ([Build the Workshop Before the Software Factory — Armin Ronacher, Earendil](../videos/2026-11-22-build-the-workshop-before-the-software-factory-armin-ronache.md), 2026-11-22, relevance 4/5)

## Open questions

- Which tool surface wins for agents: MCP, CLI, code mode or skills? Opinions conflict, from 'prefer MCP over Bash' to 'CLI for APIs with hundreds of endpoints'.
- How much should supervision UIs reveal: only the latest semantic step (Antigravity), or the full trajectory and provenance needed to catch failures like 43 repeated tool calls?
- Will agent UI protocols (AHP, ACP, A2A, WebMCP, MCP events/tasks) converge, or fragment the way the speaker warns file formats are diverging?
- What is the durable path for agent memory and continual learning: consolidated Markdown wikis, managed memory services, or local weight edits and engrams?
- Which judging approach will become standard for production agents: agent-as-judge, cheap typed decision models, or deterministic verifiers?
