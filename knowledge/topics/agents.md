## Current best understanding

**Supervision and trust are now the core design problem (Nov 2026).** Prompt instructions do not enforce human-in-the-loop. Google ADK graph workflows add a deterministic pause node for that, with tool confirmation as the approval mechanism. Real products use explicit approval gates for side-effecting actions:

- Scribant shows read-only proposal cards and nothing runs until the user approves.
- A coding agent asked permission before running a Firestore seed script.
- Agents list dangerous items, such as dashboards to delete, for human audit first.

Trust also comes from provenance. Ramp's Inspect attaches the conversation, the tools used, before/after screenshots and a verification-agent browser video to each PR. Antigravity lets users click into any subagent, message it to steer or stop it, and set read-only tool scopes per subagent. The core risk is silent wrong answers. Grounding agents in a semantic layer (Looker plus Knowledge Catalog, with PII tagging) and surfacing the definitions an agent applied both reduce it. Design rules such as a bank's colorblind-accessibility requirements now have to be encoded into agents, because the bottleneck has moved upstream to requirements and sideways to design, risk and compliance.

**Delegation model.** Leading teams run one- to two-day Kanban loops. Agents work the 'night shift' and humans validate. Devin built an Android app over 44 days, merging 40-50 PRs on days with no human messages. Delegation is moving to 'jobs, not tasks': give the agent a measurable goal such as P99 latency or layout shift, and it adds its own telemetry, alerts and reports. 'Fable class' models will brute-force a well-defined, tool-provisioned goal over runs of about 12 hours:

- Claude Fable 5.x, with Opus 5.5 as the cheaper option
- GPT-6 Astra
- Gemini 4 Argon and Carbon

The key human skills are goal definition and tool provisioning. Factories are increasingly declared as code: Warp's Terraform-style configs, and Antigravity subagents defined in Markdown. Agents can now open PRs that improve the factory itself, and Devin writes its own testing skills.

**Architecture practices.**

- **Simplicity first.** Lovable's early multi-agent setup underperformed a single main LLM until models caught up. A medium-effort default model that spawns stronger or cheaper sub-agents is now common.
- **History.** Keep the full task history as an append-only event log with parent pointers. It supports forks but not merges, and prompts are rendered per model from it. Stateless workers persisting after each turn let Lovable run 10+ hour agents through about 700 deploys a day.
- **Memory.** Memory needs deduplication and conflict resolution, not naive RAG. Vertex AI Memory Bank injected about 24 tokens versus about 1,400 for raw RAG.
- **Tool surfaces.** Keep MCP servers to roughly 50 tools or fewer, expose fine-grained primitives, and give agents empty JSON body templates to fill. Code mode (from Cloudflare, now in Codex and Pi) is an alternative to Bash.

## Open questions

- MCP vs CLI vs code mode: one speaker now prefers MCP over Bash/CLIs, while others recommend a CLI for APIs with hundreds of endpoints. Which tool surface should AI developer portals design for?
- When is multi-agent orchestration (Antigravity subagents, Gemini Teamwork Preview) actually better than a single strong model, given Lovable's experience and the caveat that delegation is 'not always better or cheaper'?
- How should approval gates and provenance UIs evolve as review checkpoints are removed once confidence in a loop is established? Who decides when that confidence has been earned?
- Markdown memory and skills bloat over time. Will continual learning move to managed memory layers like Vertex Memory Bank or to local weight edits and engrams?
- With sandbox escapes and grader gaming documented in 2026, what containment and action-based evaluation should agent platforms make visible to users?
