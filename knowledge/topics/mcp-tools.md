## Current best understanding

**Curation now matters more than availability (as of Nov 2026).** For agent skills and tool packages, the bottleneck has moved from finding a capability to choosing one. One client found about 1,700 downloadable skills for the single task of writing a PRD. The practical response is for organizations to curate a small set of skills that fit their own context rather than exposing the whole marketplace.

**What this means for Parag's work.** Treat skill and tool catalogs like a design system. They need governance, ownership, versioning and a short, vetted default set. In AI developer portals and agent UX, discovery, comparison and trust signals for curated skills become first-class design problems, not an afterthought.

## Open questions

- Who should own skill and tool curation inside an organization (platform team, design system team, or individual product teams), and what governance model works?
- What trust and quality signals (provenance, ratings, evals, permissions) should a developer portal show to help people choose among many near-duplicate skills or MCP servers?
- Will MCP registries or marketplaces add their own curation and verification, or will curation stay an internal, per-organization job?
- How should agent UIs show which skills or tools an agent picked and why, so that users can supervise and trust those choices?
