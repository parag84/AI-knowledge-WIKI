# Coding agents

> AI coding assistants and agents (Claude Code, Codex, Gemini CLI, etc.), dev workflows.

_139 active · 0 stale · synthesis updated 2026-11-23_

## Current best understanding

**Supervision is moving from reading code to reviewing evidence.** As of Nov 2026, agent runs are long: P90 went from ~2.5 min on Opus 4.6 to 14+ min, Claude worked a 12-hour run, and Codex threads have run for months. Humans therefore steer through artifacts rather than diffs: an HTML executive summary at ~70% of a session, Devin's PR plus video in Slack, Ramp Inspect's provenance (conversation, screenshots, browser-walkthrough video), structured PR templates with clear reviewer actions, and gated milestones with test tables and explicit approval. For Parag's AX and design-system work, the most actionable tools are:
- Codex's in-app browser annotations API and annotation extensibility, which make design-system components selectable and editable;
- plugin extensions such as the design-system browser with @-mention component context;
- Appshots, which capture a screenshot plus the accessibility tree;
- per-component dev inspector routes with AI-state presets, generated by skills.

**Trust comes from deterministic checks and verification, not from prose.** Turn each correction into a lint rule, type, dependency ban or API ban (useEffect and ~99% of comments banned on the Grok Bot team, with 11k PRs/month at a ~0.5% revert rate). Keep CLAUDE.md and AGENTS.md minimal and drop emphatic wording (Opus 5.5). Verification now dominates agent time and tokens (~70–90%), using inner and outer loops, TLA+, Lean, Bombadil and hooks that exit with code 2. AI reviewers earn trust through precision first; stacking diverse reviewers (Block, Review Bench) raises recall. Agents reward-hack CI, so add guards (Duolingo). Companies are standardizing on shared cloud agents and declarative "factories" with online evals: Ramp (~75% of code), Warp, Factory's L1–L4 autonomy levels gated by regret-free merge rate, and Anthropic's risk-tiered review (30k+ changes/day by Sep 2026). Write evals as critical user journeys so harnesses can be compared.

**Model defaults (Nov 2026):**
- **Claude Code:** Opus 5.5 on medium effort; raise effort before switching models. Fable 5.2 (2x Opus price) handles judgment-heavy orchestration in Claude Code projects (beta), and auto mode has been the default permission mode since August.
- **Codex:** GPT-6.1 Sol as the default, with Astra and Luna sub-agents; Ultrafast runs 8x faster at 6x the cost, which suits UI iteration.
- **Gemini:** Gemini 4 Hydrogen (~60% Terminal Bench 4) and Argon in Antigravity and AI Studio remix.

Skill curation (~1,700 PRD skills exist) and agent-friendly CLI and doc design matter more than adding new tools.

## Open questions

- Will precision-first AI reviewers and risk-tiered auto-merge hold quality, given reports that quality per PR is dropping (McKinsey) alongside low revert rates (Grok Bot, Factory)?
- Will annotation and plugin APIs for design systems (Codex in-app browser) converge on a cross-vendor standard, or will each harness (Antigravity, Claude Code, Copilot SDK) need its own integration?
- How should autonomy boundaries be set: which work stays human-gated (APIs, schema migrations) and how is regret-free merge rate measured for UI work?
- Can harness token optimizations (tool search, skill-description truncation) be made visible to skill and component authors without running per-harness evals?
- How much spec formalization (SMT checks, ambiguity clustering) do agents actually need, given that evidence for it is still thin?
